## What is actually reusable now

1. V1 already uses D3 and has [tree layout](../../src/features/family-tree/treeLayout.ts), [touch gesture handling](../../src/features/family-tree/viewportGesture.ts), [kinship](../../src/services/kinshipService.ts), [validation](../../src/services/validationService.ts) and [IndexedDB transactions](../../src/database/db.ts). Preserve those as the starting contracts.
2. `family-chart` is the only candidate with a potentially narrow interface: a **renderer-only** comparison behind V1 graph projections. It must not write to V1 stores or supply genealogical rules. No dependency decision is made in M1.
3. AncestorTree and Gramps Web may inform product questions (source attribution, branch governance, import diagnostics), but their storage, authentication and release models conflict with the current no-backend, local-only product. Their public feature descriptions are not evidence that their code can drop into V1.
4. Reuse of ideas is distinct from code reuse. Any later code import needs a pinned upstream SHA, readable license, dependency audit, synthetic data tests, mobile QA and explicit Coordinator approval.

**Verdict:** no external dependency or core replacement recommended for this Discovery Sprint. License uncertainty for AncestorTree is a blocker to code reuse; not a blocker to reading its public README.
