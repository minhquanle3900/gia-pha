# V2 discovery — V1 reuse inventory

**Source pin:** `7b745ebe553e6db6813ae2095d6f3bd11bc0ed97` (Gift Edition RC2). **Scope:** source, configuration, text documentation and tests at this commit. This is a static architecture review; no V2 behavior was implemented or exercised. Existing [RC2 QA](../handoff/gift-rc2/QA.txt) reports 327/327 tests, lint and build; those results are historical evidence, not a new run in this sprint. Existing PDF and release artifacts were excluded from content review to avoid reading or propagating possible family data.

## Baseline shape

- React 19, Vite 8, TypeScript, D3 7, `idb` 8, `vite-plugin-pwa` 2; `bun.lock` is the lockfile ([package.json](../../package.json), [vite.config.ts](../../vite.config.ts)).
- One browser origin owns one IndexedDB database `gia-pha-viet-coi-nguon-db`, DB version 1 and snapshot schema version 1. Eight stores: `settings`, `branches`, `people`, `unions`, `relationships`, `lifeEvents`, `media`, `stories` ([db.ts](../../src/database/db.ts)).
- [GenealogyContext](../../src/context/GenealogyContext.tsx) loads the entire snapshot and exposes CRUD plus graph helpers. A write reloads the whole snapshot. This is a useful V2 compatibility boundary but may be expensive for large galleries/trees; measure before optimizing.
- [App](../../src/App.tsx) and [navigation](../../src/components/navigation.ts) expose 10 tabs plus the Exhibition Hall through five current navigation groups. V2's five *spaces* are a product taxonomy proposal, not a direct rename of these groups.
- Source of truth is [genealogy.ts](../../src/models/genealogy.ts). [DATA_MODEL.md](../../DATA_MODEL.md) is background documentation; the source interfaces and validators govern implementation.

## Capability verdict for V2 concepts

| Concept | V1 supports today | Gap / boundary |
| --- | --- | --- |
| Connected member profile | Person ID can join relations, branch, events, media and stories; profile already does part of this | No central read model, stable deep-link contract, or event/media reverse indexes; aggregation should be a read-only projection first |
| Small family (`Nhà mình`) | Derive partners/children through `Union` and `Relationship` | No household ID, residence history or shared membership/permissions; avoid persisting derived family as a second graph |
| Branch space | `FamilyBranch`, `Person.branchId`/secondary IDs, `Media.branchId`, `Story.branchId`, branch filters | LifeEvent branch inferred from person; parent/subbranch semantics need product decision |
| Timeline | `LifeEvent`, FamilyYear service, history/timeline UI | Computed anniversaries lack stable record IDs; story/media chronology uses loose labels; formal linked chronology may require migration |
| Global search | Member search works with Vietnamese text normalization | Search of stories, media, branches, events is new projection and needs ranking/privacy rules; no existing full-content index |

**Recommendation:** Keep the eight-store core and its validators. Prototype V2 read models and navigation on synthetic snapshots after Blueprint approval; defer any schema decision until identity, ownership and data-portability requirements are explicit.
